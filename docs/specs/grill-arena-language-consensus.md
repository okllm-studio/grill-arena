# Interface language, Option letters, Consensus at a glance and a single Scoreboard

Vocabulary: see `GLOSSARY.md` (Session, Step, Question, Option, Selected option, Vote, Abstention, Comment, Consensus, Near-consensus, Divided, Consensual Step, Scoreboard, Facilitator, Co-facilitator, Player).

## Problem Statement

Four frictions came out of real Sessions:

1. The interface is English only. A French-speaking group reads English buttons and labels next to Questions written in French by Claude, and the Facilitator has no way to change it.
2. The body of a Question usually cites its Options as A, B, C, but the vote buttons show only the Option text. Players have to match the text by hand.
3. When a Step closes, the first thing the group wants to know is whether everybody (or almost) voted the same thing or whether the vote was divided. The results list every Question fully expanded, so this signal has to be dug out. Yet a Consensual Step is the sign of good mutual listening and should be visible at a glance.
4. On the end-of-Session page the Scoreboard appears several times (a panel at the top, a podium, a full table), plus on the Facilitator tab.

## Solution

1. The Facilitator picks the interface language (English or Français) from the Facilitator tab, at any time. It applies to everyone. The Summary generated by the server follows it.
2. Every place that shows an Option prefixes it with its letter.
3. The results of a closed Step show each Question folded, with a colour mark, the Selected option with its letter and a text distribution. A banner at the top of the results says whether the Step was consensual, or how many Questions were unanimous.
4. The Scoreboard is displayed in one place at a time, and only if it is published. The podium goes away.

## User Stories

### Interface language

1. As a Facilitator, I want to choose the interface language from my page, so that my group reads the interface in the language it speaks.
2. As a Facilitator, I want the choice to be a closed list (English, Français), so that I cannot enter an unsupported value.
3. As a Facilitator, I want to change the language at any time, even after the Opening of Step 1, so that forgetting to choose the right one at the start is not a mistake I have to live with.
4. As a Co-facilitator, I want to change the language as well, so that the group is not blocked when the Facilitator is away.
5. As a Player, I do not want to be able to change the language, so that the whole group sees the same interface.
6. As a Player, I want my page to switch to the chosen language without any action, so that I do not have to reload.
7. As a Facilitator, I want each new Session to start in English, so that behaviour is predictable.
8. As a Facilitator, I want to set the server variable `GRILL_LANG` to `fr` so that new Sessions start in French, so that I do not have to change it at every Session.
9. As a Facilitator, I want an unsupported `GRILL_LANG` value to be ignored in favour of English, so that a typo does not prevent the server from starting.
10. As a Player, I want the buttons (vote, abstain), labels, hints, statuses and error messages in the chosen language, so that nothing is left half-translated.
11. As a Player, I want the generated labels in the results (recommended, split vote, to re-ask, abstentions, my Vote) in the chosen language, so that the results page is consistent.
12. As a Player, I want the Summary shown at the end of the Session in the chosen language, so that the end page reads consistently.
13. As Claude, I want the Summary returned at the end of the Session in the chosen language, so that the working document for the spec matches what the group saw.
14. As a Facilitator, I want the content written by Claude (titles, bodies, Options, Initial prompt, Comments) never to be translated, so that the group's words are not altered.
15. As a maintainer, I want API error messages for Claude to stay in English, so that the skill contract is stable.
16. As a maintainer, I want `GLOSSARY.md` to stay in English, so that the domain vocabulary has one reference.
17. As a Facilitator, I want the language to survive a server restart with the rest of the Session, so that the group does not lose it.

### Option letters

18. As a Player, I want the letter of each Option on its vote button, so that I can match it with the A, B, C cited in the body of the Question.
19. As a Player, I want the same letter on the result bars, so that I can read the results against the Question.
20. As a Player, I want the letter in the live distribution, so that the numbers are attached to the right Option.
21. As a Facilitator, I want the letter in the tie-break selector, so that I pick the right Option among the tied ones.
22. As a Facilitator, I want the Summary to show the letter of the Selected option, so that the working document is unambiguous.
23. As Claude, I want the skill to tell me to use consecutive capital letters (A, B, C…) as Option identifiers and to cite them in the body, so that the page and the text agree.
24. As Claude, I want a Step with an atypical Option identifier to still be accepted and shown as is, so that a small deviation does not block a Session.

### Consensus at a glance

25. As a Player, I want each closed Question to be folded by default, so that I can scan the whole Step quickly.
26. As a Player, I want a colour mark on each folded Question (green for Consensus, orange for Near-consensus, red for Divided, neutral for not assessed), so that I see the level of agreement at a glance.
27. As a Player, I want the level also written as text, so that I get the information without relying on colour.
28. As a Player, I want each folded Question to show its Selected option with its letter and the distribution in text (for example "A 5 · B 1 · abst. 0"), so that I get the picture without unfolding.
29. As a Player, I want a Question to re-ask to show as Divided, with no Selected option, so that a Split vote is recognised as a disagreement.
30. As a Player, I want to unfold a Question to see the bars, the Comments and my own Vote, so that detail is one click away.
31. As a Player, I want an indicator on a folded Question that has Comments, so that I do not miss them.
32. As a Player, I want a banner at the top of the Step results saying "Consensual Step" when every assessed Question reached Consensus, so that I see good listening at a glance.
33. As a Player, I want the banner to read "N Questions out of M unanimous" otherwise, so that I see how close the group was.
34. As a Player, I want a Near-consensus not to make the Step consensual, and to be flagged orange in the list, so that the banner stays a strong signal.
35. As a Player, I want the banner to count only assessed Questions, so that Questions with fewer than two voters do not distort it.
36. As a Facilitator playing alone "around the table", I want no banner and no Consensus mark when no Question is assessed, so that a single entered agreement is not displayed as a false consensus.
37. As a Player, I want abstentions ignored in the level, so that a deliberate Abstention does not count as disagreement.
38. As a Player, I want a Question with fewer than two voters to show a neutral mark, so that the absence of information is not read as agreement or disagreement.
39. As a Player, I want the same folded view and banner for the results of past Steps, so that I can review them in the Results tab.
40. As Claude, I want the closing result to carry the consensus level of each Question and of the Step, so that I can use how divided the group was in the next Step.

### Single Scoreboard

41. As a Player, I want the Scoreboard shown once, so that the end page is not repetitive.
42. As a Player, I want no podium, so that there is no second rendering of the same scores.
43. As a Player, I want the Scoreboard on the end-of-Session page only if it has been published, so that nothing appears that the Facilitator withheld.
44. As a Player, I want the top button and panel to show the Scoreboard during the Session once it is published, so that I can follow it when the Facilitator publishes early.
45. As a Player, I want that button and panel to disappear on the end page, so that the Scoreboard is not displayed twice.
46. As a Facilitator, I want the Scoreboard block of my tab to be hidden once the Session has ended, so that I do not see it again next to the end page.
47. As a Facilitator, I want to keep the publication button and the Scoreboard in my tab during the Session, so that I can review it before publishing.

## Implementation Decisions

- **Session language setting.** A new Session setting with two values (English, Français). It is part of the state sent to all Players, persisted with the Session and restored after a restart. Unlike the Initial prompt and the live distribution setting, it is never locked.
- **Who can change it.** The Facilitator and Co-facilitators. Players are refused. Same authorisation family as Opening and closing, not the Facilitator-only settings.
- **Initial value.** English, or the value of the server variable `GRILL_LANG` when it names a supported language; any other value falls back to English without failing.
- **One translation catalogue**, shared by the server (Summary) and the browser (interface), so that each interface word exists once per language. The browser asks for the catalogue once; the server uses it to render the Summary. A missing key in a language falls back to English.
- **Scope of translation.** Fixed labels, buttons, hints, statuses and messages of the Player and Facilitator pages, the generated labels of the results, and the fixed skeleton of the Summary (title, Step headings, "to re-ask", "split vote", "recommended" / "not recommended", "re-asked from", Scoreboard heading, Point). Not translated: content provided by Claude or by Players, API error messages, `GLOSSARY.md`.
- **Summary language.** The Summary, shown on the end page and returned to Claude at the end of the Session, is generated in the current language of the Session. Changing the language after the Session ended is not a case to support.
- **Proposed French wording** (to be adjusted at implementation): Step → Étape, Player → Joueur, Facilitator → Animateur, Co-facilitator → Co-animateur, Opening → Ouverture, Vote → Vote, Abstain → S'abstenir, Comment → Commentaire, Scoreboard → Tableau des scores, Point → point, Summary → Synthèse, recommended → recommandée, Split vote → Vote partagé, to re-ask → à reposer, Consensus → Unanime.
- **Option letters.** The Option identifier is displayed before the text wherever an Option appears: vote button, result bar, live distribution, folded Question line, tie-break selector, Summary. No validation is added on identifiers: an atypical one is displayed as is. The skill documentation asks Claude for consecutive capital letters starting at A and for the body to cite Options by these letters.
- **Consensus computation (server side).** Per closed Question, from the cast Votes only: Consensus when all voters chose the same Option; Near-consensus when exactly one Vote differs from the rest; Divided otherwise, including a Split vote and any Question to re-ask; not assessed when there are fewer than two voters. Abstentions, including Players who did not answer, are ignored. The level is part of each Question's result in the Players' view and in the result returned to Claude.
- **Step banner (server side).** Per closed Step: the number of assessed Questions, the number at Consensus, and a consensual flag set when every assessed Question is at Consensus. When no Question is assessed the Step has no consensus status and no banner is shown. Near-consensus does not count as unanimous.
- **Folded results.** Closed-Question results are folded by default, in the Results tab and wherever a closed Step's results are shown. The folded line carries: the colour mark and its text label, the Question Number and title, the Selected option with its letter (or "to re-ask"), the text distribution with abstentions, and a Comment indicator. Unfolded: bars, Comments and the Player's own Vote. Colours: green, orange, red, neutral grey; the text label always accompanies the colour.
- **Scoreboard display.** The podium is removed. The Scoreboard appears in one place at a time, only when published (end of Session, or published early by the Facilitator): the top button and panel during the Session; the end-of-Session card once the Session has ended, at which point the top button and the Facilitator tab block are hidden. The Facilitator's publication button and its review of the Scoreboard before publication are unchanged during the Session.
- **Documentation.** The skill description is updated (Option letters, Summary in the Session language, consensus fields of the result). The README is updated (language setting, `GRILL_LANG`, consensus, single Scoreboard). `GLOSSARY.md` already carries Consensus, Consensual Step and the revised Abstention.

## Testing Decisions

- **One seam: the HTTP API**, as in the existing server tests, which drive the server through real requests with Players, a Facilitator and Claude's token. A good test checks externally visible behaviour (state, result, Summary) and not how it is computed.
- Tested through the API:
  - the language setting: default English, the `GRILL_LANG` initial value and fallback, change by the Facilitator and by a Co-facilitator, refusal for a Player, visibility to Players, persistence across a restart, and no lock after the Opening of Step 1;
  - the Summary in each language, including the fixed skeleton and the unchanged Claude-provided content;
  - the consensus level per Question for each case (unanimous, one dissenting Vote, divided, Split vote, Question to re-ask, abstentions ignored, fewer than two voters) and the Step figures and consensual flag, in the Players' view and in the result returned to Claude;
  - the Scoreboard availability rules already covered keep passing; a Scoreboard not published is still absent from the end-of-Session view.
- The pure vote-counting logic can reuse the style of the existing arbitration tests for the consensus level.
- **Not covered automatically** (browser rendering, as today): Option letters on every control, folded Questions and their colour and text labels, the banner, the language switch on a Player's page, the removal of the podium, and the hiding of the Scoreboard button and block at the end. These go into a manual checklist run in a browser, including on a phone and behind the tunnel.

## Out of Scope

- Per-Player language choice (to reconsider only if the need appears).
- Languages other than English and Français.
- Translating the content produced by Claude, the Initial prompt, Comments, API error messages or `GLOSSARY.md`.
- Distinguishing a deliberate Abstention from "not answered yet" in the Player view.
- Consensus statistics over the whole Session (for example "x Steps out of y consensual") on the end page.
- Any change to scoring rules or to the Points earned.
- A server-side refusal of Option identifiers that are not letters.

## Further Notes

- Abstention is a deliberate choice not to bias the result when one feels poorly placed to answer; this is why it is ignored by Consensus rather than treated as dissent.
- The "Consensual Step" banner is meant as a strong positive signal of mutual listening, hence strict Consensus on every assessed Question.
- Documents that this change will make obsolete once implemented: the README parts on the Scoreboard and the end-of-Session page, and any text mentioning the podium.
